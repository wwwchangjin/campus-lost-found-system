# 校园失物招领与暂存认领系统

一个面向高校师生的校园失物招领与暂存认领系统，旨在解决校园失物信息分散、查询不便、物品管理不规范以及认领流程不透明等问题。

## 一、项目简介

在校园日常生活中，学生和教职工经常会遇到物品遗失或拾得他人物品的情况。目前，失物信息主要通过微信群、QQ 群、校园论坛以及线下失物招领点进行传播和管理，存在信息分散、更新不及时、查找效率低、认领流程不统一等问题。

本项目计划建设一个统一的校园失物招领与暂存认领平台，为失主、拾得者和暂存点工作人员提供信息发布、物品查询、暂存管理和认领核验等服务。

## 二、项目建设目标

1. **统一信息发布：** 提供寻物信息和拾物招领信息的统一发布入口。
2. **提高查找效率：** 支持按照物品类别、时间、地点和关键词检索失物信息。
3. **规范暂存管理：** 实现物品登记、分类、编号和暂存状态管理。
4. **规范认领流程：** 通过归属证明和工作人员审核降低冒领风险。
5. **保障信息安全：** 保护用户个人信息，区分公开信息与内部核验材料。
6. **实现流程追踪：** 记录物品接收、保管、审核和交付等关键业务环节。

## 三、主要用户角色

| 用户角色 | 主要职责 |
|---|---|
| 失主 | 发布寻物信息、查询招领信息、提交认领申请 |
| 拾得者 | 发布拾物信息、联系或移交暂存点 |
| 暂存点工作人员 | 登记物品、管理库存、核验认领、确认交付 |
| 系统管理人员 | 管理用户权限、处理异常情况、维护系统运行 |

## 五、项目协作与 GitHub 工作流

项目使用 GitHub 进行版本控制、任务管理和团队协作。

### 1. 分支管理

项目采用 `main` 作为主分支，并按照任务类型创建工作分支。

| 分支前缀 | 用途 | 示例 |
|---|---|---|
| `docs/` | 文档编写与修改 | `docs/research-report` |
| `feature/` | 新功能开发 | `feature/lost-item-publish` |
| `fix/` | Bug 修复 | `fix/claim-validation` |
| `test/` | 测试相关工作 | `test/claim-workflow` |

任务完成并合并后，分支可以保留，不强制删除。

### 2. 标准协作流程

每项工作原则上按照以下流程进行：

1. 创建 GitHub Issue，明确任务内容和验收标准。
2. 根据 Issue 创建对应的工作分支。
3. 在工作分支上完成开发或文档修改。
4. 提交 Commit，并关联对应 Issue。
5. 创建 Pull Request，说明本次修改内容。
6. 邀请其他成员进行 Code Review 或文档 Review。
7. 审核通过后合并到 `main` 分支。

### 3. 代码与文档管理

- `main` 分支作为项目稳定版本。
- 禁止绕过分支保护规则直接向 `main` 推送。
- 所有正式修改通过 Pull Request 合并。
- 每个任务尽量对应明确的 Issue 和提交记录。
